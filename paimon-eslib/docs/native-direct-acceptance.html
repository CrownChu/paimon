Paimon ES 模块直接调用 native：验收结果

验收日期：2026-10-19 UTC。代码提交：11cf8416abc8ea9e92dc16eab0754eb2e70e491f。分支：codex/paimon-es-native-direct-20261019。

通过：Paimon 模块已内置 native 写入与读取桥接，移除外部 ESLib 和 Java Lucene 生产依赖。独立 Java 进程在没有这些 JAR 的 classpath 上生成真实提交的 Paimon 表，原 C++ SDK 的静态与共享库构建均成功查询。源码已提交；平台运行包在本地构建和验收，本轮没有公开发布 SO。

改动与范围

基线为 GitHub Paimon 最近的分组索引修复提交 b34c28a3f633f5d2ef2a2aaad6c5a3130340014d，保留该基线的表级标量查询修复。改动集中在 paimon-eslib 和根 Maven 许可证识别配置；Elasticsearch、elasticpp 引擎、独立 ESLib 和 C++ SDK 源码没有改动。

工厂直接创建模块内 native builder/searcher，经 JNA 调用已验收的 C ABI v1。字段模型与转换代码在模块内编译，JSON 使用 Paimon shaded Jackson。writer 在失败或未完成封存时也能正确清理自己持有的工作目录；标量数组、NULL 占位、通配符和分组索引保守回退语义保留。归档继续使用 ESM1 v3、elasticpp 后端标识和原 native descriptor，不变更 C++ SDK 协议。

实现和构建说明见 HTML 实施说明及模块 README。迁入的公开桥接及模型保留 Elastic License 2.0、来源 commit 和逐文件摘要；现有 Paimon 文件保留 Apache License 2.0。

真实表与独立进程

GenerateNativeTableFixture 使用当前 GitHub Paimon 的 catalog、写入、提交、索引元数据与快照 API，生成 Parquet / ORC × HNSW / INT8 HNSW / DiskBBQ 共 6 张合成数据表。每表先写入 128 行、两个分区和四个索引分片，再提交索引快照 3；随后追加 8 行未建索引数据到第三个分区，形成快照 4。Java 对两个快照独立全表读取，生成用于 C++ SDK 差分比较的 oracle。

消费进程使用本次打包的 Paimon 模块 JAR、模块自己的平台 classifier、JNA 与常规 Paimon 依赖。编译和启动都没有使用外部 ESLib 或 Java Lucene JAR，且在进程内检查原 ESLib builder、原 native binding 和 Java Lucene IndexWriter 均不可加载。C++ SDK 固定在 e11483e0dc851eb51c26054fcfd0eb0613291bca，使用原有静态、共享库测试二进制。

上游 Paimon 生产依赖与 common tests JAR 需要先按仓库说明构建。本轮使用任务独立的 Maven 本地仓库构建上游依赖，未覆盖其他任务的同版本快照 JAR。最终模块验证未使用 fast-build 跳过质量检查。

运行需普通模块 JAR、同版本平台 classifier、JNA 与 Paimon 常规运行依赖。默认构建不下载 SO。旧 native ESM1 v3 归档已验证兼容；旧 Java / ESM1 v1/v2 索引需要原 reader 或重建。当前向量维度上限 1024，dot_product 要求单位向量；非有限标量、GEO、未验收的 fuzzy 查询和向量自定义调参仍明确拒绝。IK 需要固定的三份字典文件与 ES_PATH_CONF。

平台包尚未公开发版，Dadi 公开再分发材料的既有条件仍需另行完成。性能压测、Spark/Ray 集群运行与生产部署不在本轮验收范围，不声称性能收益。
